# Interface

This spec governs the live application's layouts, motion and palette (Moss, light and dark).

## Tokens, type and identity

Role tokens: light paper `#f3f5f2`, surface `#ffffff`, ink `#12261f`, pine band `#12352b`, coral action `#c4461f`. Dark paper is `#0d1915`, surface `#14241f`, ink `#e8f0eb`, pine band `#1f4a3b`, coral action `#ff7449`. Derive hairlines from ink. Flat surfaces and a small shadow; photographs provide colour. Gradients may support photo legibility, never decorate the page.

Anton is display type and Bricolage Grotesque is UI/body type, loaded with `next/font/local`. Dates and prices use tabular numbers. The ticket/compass identity has standalone outlined SVG variants for light, dark and pine surfaces; header colour follows the page before paint. The adaptive SVG favicon and PNG/ICO renditions use the symbol alone.

Follow the system colour scheme on first visit. The header menu switches light/dark and remembers the choice when storage permits. Failure to persist must not prevent switching for the visit.

## Home

The header carries the logo, a Saved Concerts shortcut with an animated count, and a menu with Your Taste, theme and optional account controls. The menu also keeps Saved Concerts. The logo returns to the resting home page. Search replaces the home sections; navigation never submits a Search. A reload, or Back from another page, returns to the tab's latest Search without starting another: the words stay in the box and the Poster rises as on a view change instead of replaying its narrowing. Home sections stay hidden before paint so they never flash above it. A Search the reload interrupted offers Try again. The logo forgets the kept Search.

The headline changes through example ways to Search using the researched `react-split-flap` LongFlap engine. Adapt its clipped, two-stage fold to the existing Anton/coral/Moss typography: no default hardware tiles, borders, shadows or library fonts, and no overlapping full text layers. Load the engine after hydration with a static first phrase; reduced motion stays static. The main Search box has one input, an explicit location button and Search action. The input rotates the three examples while it is empty and unfocused on home. Focus clears the example completely; blur restores it only when the input is still empty. Typed text is never replaced. After a Search the empty input stays blank until home returns. Reduced motion uses static text. Examples also appear as buttons below the box.

A labelled photo strip shows cached public example Posters, refreshed by the authenticated nightly warm job. Neither a visit nor an example click can make a paid Search. Wait for the public example request to settle before revealing the guide below the strip, so navigation cannot paint the green band in the strip’s eventual space. The request has a five-second bound; a failure still reveals the guide. A cache miss leaves the strip out and puts the example words in the input with an explanation. A visitor may explicitly submit those words as an ordinary Search. Expired source dates stay out. Spotify-connected visitors see their own separate shelf instead of the public strip.

How a Search works replays the public Search recording “Calvin Harris in SoCal next May”, captured November 8, 2026, independently of the changing home cache. Label it as a replay. Type the words at 34 ms per character, then spring the understood chips into place. Count the 40 Concerts considered while the recorded candidate names arrive in a short stagger. Darken the chosen names and dim the others. Finish that narrowing animation, then hold it for 200 ms before raising the photo/date/venue picks and first reason. Hold the finished state, then lift and clear all five content groups together before repeating. Keep all three panel surfaces opaque throughout; animate content inside the third surface rather than the surface itself. Measure each panel's finished content at the current width; desktop panels share the tallest height, stacked panels retain their own heights. Stop the sequence out of view and cancel it on navigation. Reduced motion shows the complete final state without typing or looping. The source recording supplies every displayed fact; the replay starts no Search or paid request. Make it yours offers location and Taste; it retires once Spotify is connected. The footer links Privacy and the owner.

Location is requested only on an explicit button press. Forget my location deletes the stored coordinates. Typed places win over shared coordinates, and no place comes from an IP address.

## Working view

The live SSE stream drives status, understood Artist/sound/place/date context and the candidate cloud. Candidate names arrive from `candidates`, never invented or taken from Spotify. Show up to 40 shortlisted Artist names while ranking. On `poster`, chosen names spring from scale 1.12 while other names dim to .18 and scale .94. Hold the narrowing for 950 ms (600 ms for an empty Poster), then reveal the cards with a staggered vertical crop and photo zoom from 1.18. Each complete chosen pill, including its background, travels into its title over 950 ms: the UI text hands over to display type early and the pill background disappears near landing. Solo Tickets use the same name flight. Cached examples first allow 1400 ms to see their candidate names. These are presentation timings; they do not delay the network request or add model work. Reduced motion skips the holds. There is no percentage progress or legacy fixed loader sequence. An empty Poster removes the cloud and offers useful changes.

## Poster and Ticket

Grid and List use two icon buttons with accessible names and pressed states. Both show exactly the same Recommendations in rank order. Grid follows the count: 1 a solo Ticket, 2 halves, 3 a large pick with two stacked, 4 halves, 5–8 a large pick, stacked picks, then thirds/halves. Phones stack the Concerts. Photo captions have a dark backing sized to their full content, with reserved space for the date and bookmark; bright photos and long Artist names must remain readable. Omit a source title that only repeats the Artist, including equivalent “and”/“&” spellings, while retaining actual tour and festival titles. List shows date, Artist, rest of source title, venue, time, reason and photo where reported. At three or fewer picks, list the other candidate Artists, initially 18 with a Show more button.

A Concert opens an accessible Ticket dialog. The source photo travels to its dialog frame over 700 ms with object-fit cover and changing frame dimensions, preserving its crop. Only after it lands does the sheet unfold from behind it over 600 ms; details stagger into place and the close button springs in. Closing folds details behind the photo over 320 ms, then returns the photo to the actual Grid, List or solo photo frame over 600 ms. Interruption and resize must restore photos and remove overlays. On the owner’s later November 8 revision, smoothly expand and collapse the sheet with the dates over 500 ms. Keep the desktop photograph at its opening dimensions and crop, centered within a matte column rather than enlarging it to fill the taller sheet. On phones smoothly reduce the photo height to make room and keep Tickets and Save side by side. The recorded eight-date case must fit the 1280×800 and 390×844 viewports without scrolling details. Allow overflow only when a smaller viewport or longer source content actually requires it; keep Close reachable. Collapsed dates leave keyboard navigation immediately. The details use the same source facts as Saved Concerts: Artist panel, first-Ticket hint, date and venue time zone, reason, price only if known, next presale before general sale, other dates grouped by venue, and the source ticket link. A single Recommendation also exposes its Ticket directly on the Poster.

On November 8 the owner superseded the dialog-only decision: provide reversible Save/Unsave toggles in the Ticket and 44px bookmark buttons on Grid/List/solo photos. Photo bookmarks work independently of opening a Ticket and reflect the same saved state as the dialog, header count and Saved Concerts page. Keep Skip and drag, the deck and its end panel removed. Saving or removing a save confirms device/account storage without closing or advancing. Serialize pending changes per Concert; a failed account removal restores only that Concert, preserving concurrent saves of others. Photo actions expose success/failure feedback without shifting the Poster. Dismiss completed Save/Unsave feedback after four seconds, restarting its lifetime for a new action; keep pending account writes identifiable until completion. A saved check and text work without colour alone; failed storage never claims success. Account failure rolls back the optimistic save and permits retry. Escape, close and backdrop restore focus to the opening Concert. The Artist panel remains a nested accessible dialog.

List switching fades/lifts the old view over 200 ms then raises the new Concerts over 550 ms with a 40 ms stagger and a small photo zoom. Persist the choice; arrow keys switch views and move focus. Save fills from the click point, springs its check, and rolls the header count while preserving storage failure behavior. The home strip expands and desaturates its photos, and the hero is a split-flap headline. Library half-face glyph coordinates must align when settled, and their backgrounds must change with the page palette without an independent color transition. Reduced motion shows end states immediately. Most motion uses transforms and opacity; the finite photo/pill flights and sheet/card reveals also animate frame dimensions and clipping, and there are no pointer-following effects. Keep touch controls at least 44px. Verify 390px and 1280px widths, both themes, reduced motion, keyboard focus and no horizontal document overflow. Physical-device frame rate and screen-reader acceptance are separate from automated Chromium checks.

## Shared Poster

A Share button sits beside the Grid and List views, in a solo Ticket's actions and as an icon beside Save in the Ticket dialog, so the dialog keeps its height. The visitor sees "Link copied" or "Shared" briefly, and a failed link says so beside the button. Closing the share sheet is not a failure.

`/p/[id]` opens a Poster at once, without the working view or the name flight, under a "Shared Poster" pill, the Search's reading as a heading and chips, and the date it was made. A Ticket link opens its dialog without a flight. When every Concert has passed it says so, and an unknown or expired link has its own page. A Search box below the Poster sends its words to the home Search. The link preview image is 1200×630 in the dark Moss palette, set in Anton: the label, the heading and up to five picks with dates and cities. Satori cannot read WOFF2, so `app/fonts/anton.ttf` is the same typeface unpacked for it.

## Empty, errors and existing features

An empty Poster says Nothing here fits. Offer a Search over the next three months using the understood Taste/place, a worldwide Search when the API supports a named Artist, and editing the Search. Actions that submit still require a fresh bot token. Elsewhere remains a source-only board for an empty place/Taste Search. It never becomes a model-ranked Poster.

Keep Turnstile, visitor/spend limits, Search-off 503, actionable errors and truncated-stream retry. The API pipeline and source-fact assembly remain the authority. Keep Spotify exact-name matching, its separate data path and hide/paging controls; Taste imports; optional accounts and synced saves; Privacy and credits.

## Artist panel, hint and reports

An Artist's name opens public Last.fm facts and a Spotify page/search link without a model. Missing facts stay out; if Last.fm knows nothing, say so and keep the Spotify link. The first-Ticket hint disappears after opening a panel or saving and stays dismissed on that device.

After a Search, Tell us opens a note. Reports use Resend and preserve existing limits and configuration. They include Search, interpretation, error and Poster facts, never location coordinates or connected Spotify data. Privacy opens in a separate tab so the active Search survives.
